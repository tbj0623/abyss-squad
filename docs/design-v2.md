# 深渊小队 v2.0 — 升级设计纲要（Lead 决策版）

> 本文是 v2.0 的实施契约。所有子代理按此执行，接口不变式以本文为准。

---

## 零、为什么要做 v2.0

v1.0 已经"完整"：12 职业 / 60 遗物 / 36 进化 / 20 敌人 / 8 首领 / 6 生态 / 10 房间 / 36 事件 / 5 契约 / 32 元进度节点 / 24 成就，平衡五档达标，包体 5.28 MB，无崩溃。

但**深度不足**，具体表现为三个结构性问题：

1. **元进度是纯数值堆叠**。32 个节点全是 "+6 生命 / +5% 伤害 / +3% 移速"。打通一次后，玩家变强的方式只是数字变大，**玩法没有变化**，长期目标感很弱。
2. **难度是 5 个固定档位**，没有"自己给自己加难度换奖励"的机制。高难度通关后无事可做，缺少 Hades Heat / StS Ascension 那种"难度即内容"的长期曲线。
3. **部分内容名义存在但机制单薄**，需要审计后逐个补足（遗物/进化里有多少是真改玩法、多少只是加数字）。

v2.0 的目标不是"更多内容"，而是**让已有的内容真正产生玩法差异**。

## 一、v2.0 三大支柱

### 支柱 1：契约词条（Pact / Heat 系统）— 最高优先级

把现有 5 档固定难度，扩展为「基础契约 + 可自定义词条」双层结构。

**规则**
- 5 档基础契约保留不动（漫游/远征/试炼/深渊/炼狱），保证既有平衡与存档兼容。
- 新增 **12 条独立词条**，玩家可任意开关组合。每条词条有 `heat` 值（1–3 级）。
- 开启词条会提高本局结算的**星尘与深渊印记倍率**，倍率 = `1 + 总heat × 0.12`。
- 词条**必须改变玩法**，不能是纯数值：
  - 例：「精英狂潮」——精英出现频率翻倍，但掉落遗物稀有度 +1
  - 例：「无光视野」——屏幕四周出现视野遮蔽，但星尘 +30%
  - 例：「弹药枯竭」——弹道数量 -1，但伤害 +35%
  - 例：「首领狂怒」——首领多一个阶段，但印记 +2
- 词条解锁：需要先以对应基础契约通关一次，逐步开放（保留成长感）。
- 词条选择界面：新增一个屏幕 `PactScreen`，在角色选择页提供入口。

**存档兼容**：词条 id 集合序列化进 `Game`，`Codec.VERSION` 升到 7，并保留 v6 迁移（旧档 = 无词条）。

### 支柱 2：元进度重构 — 从"数值"到"选择"

现有 32 节点不动（保证已投入的印记不作废），但**新增第二层：天赋牌（Doctrine）**。

**规则**
- 新增 **18 张天赋牌**，分 6 组（对应 6 流派）。
- 不提供数值加成，而是提供**开局条件/规则改写**：
  - 「余烬开局」——初始遗物固定为一件余烬系稀有遗物
  - 「双重进化」——每局可进化两条线（原本只有一条）
  - 「献祭契约」——最大生命 -25%，但每次升级额外获得一次三选一
  - 「星尘债务」——开局 -50 星尘，但商店价格 -25%
- 每局开始前**只能装备 1 张**。牌通过成就/通关特定契约解锁。
- 这给玩家"换一种打法再来一局"的动机，而不是"再刷 100 局把伤害点满"。

**实现要点**
- 天赋牌是 `Game` 的开局修饰器，在 `beginRun()` 里应用。
- 需要 `Codec` 序列化 `doctrine` 字段。
- 新增 `DoctrineScreen` 或在 `CharScreen` 增加一栏。

### 支柱 3：内容去水 — 让每个遗物/进化都是"真机制"

**审计驱动**：先把 60 遗物 + 36 进化按 a/b/c/d 分类（a=真改玩法，b=纯数值，c=太弱，d=重复）。

**改造原则**
- **每个流派的 10 件遗物里，至少 6 件必须是 a 类**（真改玩法）。
- 纯数值遗物保留，但必须**附带一个行为钩子**。例："+15% 伤害" → "+15% 伤害，且暴击时对周围 60 范围造成 30% 溅射"。
- **36 条进化线，每条都要改武器行为**，不能只是伤害数字。检查清单：
  - 弹道数量 / 形态变化
  - 穿透 / 弹射 / 分裂
  - 爆炸 / 范围伤害
  - 链式 / 持续伤害
  - 轨道 / 召唤 / 炮台
  - 蓄力 / 光束 / 地雷
- **36 个事件**按机械结构去重，重复结构的改写或替换。

## 三、接口不变式（所有实施代理必须遵守）

1. **存档向前兼容**：`Codec.VERSION` 从 6 → 7。必须保留 v5/v6 读取路径，旧档读入后 `pactMods=0`、`doctrine=-1`、`pactHeat=0`。
2. **不删除、不重编号**任何已有的 `Relics` / `Evolutions` / `Events` / `Enemies` / `Bosses` / 元进度节点 id —— 这些 id 出现在存档里。
3. **`valid()` 必须继续返回 true**：每次改内容表都要同步长度。
4. **确定性不可破坏**：所有随机走 `RunRandom`，同一 seed + 同一输入 → 同一结果。
5. **`core` 不引 Android 依赖**：支柱 1/2 的全部逻辑必须在 `core`，`app` 只做展示与输入。
6. **平衡红线**：改造后 5 档基础契约胜率必须仍在
   `漫游 80–92 / 远征 55–70 / 试炼 38–52 / 深渊 22–35 / 炼狱 10–20`，
   且"零词条"状态下的数值不得漂移超过 ±6pp。
7. **公共方法签名不改**：新增能力用新增方法/字段。
8. **构建必须常绿**：每次改完 `core` 立刻 `javac`；仓库被多代理共用，一次编译失败会卡住所有人。
