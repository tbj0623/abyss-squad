# v2.7.0-beta.1：战斗公平性与联机自动选择

2026-11-02 · Android 公开 Beta · 基于 v2.6.0-beta.1

## 为什么把这轮放在「公平」上

把旧版研究建议与现有实现逐条核对后，确认三选一进化、抽取去重、买空重摆、Boss 转阶段缓冲等已在此前版本落地。此时继续叠系统只会增加维护面；更有价值的是让写在规则表里的承诺，真正覆盖到玩家走过的代码路径。

参考同类作品的一个共性：Brotato 允许自动开火与可选手动瞄准，并提供难度调整；手机游戏的高难度应来自理解多重威胁与走位，而不是无法辨认的前摇。来源：https://store.steampowered.com/app/1942280/Brotato/

## 这次发现的实际缺陷与修复

1. **敌人预警下限只存在于数据层，没有接入实战**。Enemies.TELEGRAPH_FLOOR 已规定 0.45 秒，Enemies.valid 也在全契约矩阵上测试，但 Game.startTelegraph 原先直接计算表值 × 行为倍率 × 精英缩短。比如噬星虫基准 0.35 秒、精英 0.2975 秒，实际突破了承诺。现在每次蓄力经过最终下限钳制，20 敌种 × 5 契约 × 普通/精英共 200 种条件都检查到 e.telegraph 与 e.windup。
2. **拉长预警但不凭空改变攻击节奏**。新增的预警时长继续从后续冷却中等量扣除，沿用已有的冷却最低阈值；测试逐组合验证「预警 + 扣回冷却」的关系，避免以可读性为借口偷偷削弱或加速敌方。
3. **联机掉线或 50 秒超时固定选第 1 张牌**。此前 Game.updateChoice 一律 choose(id, 0, 0)，既可能拿满层转钱，也可能无视第 2、3 张可用进化牌。现在只对自动兜底采用确定性选择：有效卡优先、进化牌优先且已解锁的高阶线优先；遗物考虑职业适配、完成三件不同同流派共鸣、稀有度以及满层/满槽。该判断不消耗随机数，仍维持主机权威同步；真人手选完全不变。
4. **异常节奏输入安全性**。Enemies.telegraphSeconds 对 NaN 与无穷值原先可返回 NaN，现在显式把非有限值落到有界的安全计算路径。

## 自动验收

- scripts/test.ps1 扩至 19 套，包含新增 CombatFairnessTest；所有已通过。
- ContentAudit 通过 1,400 项检查，0 项硬失败，3 项预算型提示（原有提示，不掩盖）。
- CombatFairnessTest 覆盖 200 个实战预警状态、每个状态的冷却预算、NaN/Infinity 的表级辅助函数、多人掉线自动选择的真实授奖路径。
- 同源 Java 构建完成后运行 PlayProbe：8 种子 × 5 契约 × 12 职业 × 3 选牌策略 = **1,440 场**，无崩溃、无超时、无 NaN/溢出。三策略胜率约 60% / 58.1% / 54.2%；主策略契约 0–4 为 100% / 91.7% / 60.4% / 27.1% / 11.5%。守卫主策略 95%，霜灵 37.5%，显示角色差异仍需真人配对验证。
- 保持 Codec v11、既有存档字段和发布签名不变；Android versionCode 2701。

## 公开 Beta 的边界

机器人固定走位、自动瞄准的胜率不是玩家群体的胜率；不能据此声称「12 职业已经平衡」。低端真机长局性能、不同屏幕 DPI 的文本布局、Android 实机手势、四设备弱网重连及无障碍专项仍需要真人设备验收。此次修改聚焦可证实的战斗/选择契约，不宣称作品已完美。
