# 深渊小队 / Abyss Squad — v2.4.0-beta.1

> **公开测试版**：原生 Android 俯视角割草 + Roguelite 构筑。代码、程序化生成的美术与音频以 MIT 许可证开源。此版本通过核心自动化回归和发布构建验证，但尚未完成多机弱网、低端真机与无障碍专项验收。

俯视角动作割草（Survivors-like）× Roguelite 构筑。一个人可以通关，也可以局域网最多四人共斗。
全部美术与音频均由脚本程序化生成，**没有使用任何第三方素材，没有内购、广告、账号或联网上报**。

- 公开下载：[GitHub Releases](https://github.com/tbj0623/abyss-squad/releases)（请优先安装最新 Beta）
- 本地构建：`app/build/outputs/apk/debug/app-debug.apk`；发布包在 `app/build/outputs/apk/release/`
- 兼容：Android 8.0（API 26）及以上，横屏
- 包名：`com.dilao.abysssquad`

## 三、核心系统

### 构筑
- 每清一个房间抽一次遗物三选一（精英房两轮），可花星尘重掷。
- **流派共鸣**：同流派遗物叠到阈值触发额外效果，6 个流派有各自的乘区。
- **进化**：铁匠铺里为当前职业选一条进化线，三阶进化需要对应遗物前置；进化会改变武器形态而不只是加数值。
- **职业基线**：12 个职业的伤害/攻速/生命/移速/暴击/弹道全部不同，不是换皮。

### 地图与经济
- 15 节点星图，每次给 2–3 条岔路，房间类型在地图上提前可见（含异变预览）。
- 星尘（局内货币）用于商店、重掷、神龛；深渊印记（局外货币）用于解锁职业与元进度树。
- 宝藏房必须先击退守卫；挑战房有 3 种目标（守星环 / 生存 / 灵魂狩猎）。

### 难度
- 5 档契约同时调整敌人血量、伤害与行动节奏，而不是简单加血。
- 每档契约的真实胜率由自动探针（`tests/PlayProbe.java`）校准，详见第七节。
- 第 4 档起解锁「深渊印记」产出加成，第 5 档为硬核向。

### 元进度
- 32 节点 / 6 组 / 153 级：生命、伤害、移速、经验、星尘、暴击、磁吸、闪避冷却、攻速、射程、回复、护甲、流派加成、复活次数、初始资源…
- 解锁 6 个额外职业、5 档契约上限、24 个成就、图鉴解锁。
- 元进度存档与局内存档相互独立：`.sav`（局内，原子写入 + CRC32）与 `SharedPreferences`（局外 JSON）。

### 联机
- 局域网 TCP，房主权威（host-authoritative），最多 4 人。
- 协议：输入同步 + 全量状态快照（`Codec` VERSION 10）+ CRC 校验封包。
- 掉线重连、房主离开结束房间、版本不匹配有明确提示。
- 只适用于可信局域网，无公网匹配 / 账号 / NAT 穿透 / TLS / 排行榜。

## 四、技术实现

### 架构
```
core/   纯 Java，零 Android 依赖 —— 权威模拟（可独立跑测试与数值探针）
app/    Android 层 —— 只负责输入、渲染、音频、存档
```
- `core/src/com/dilao/core/`：`Game`（战斗权威模拟）、`Content`、`Relics`、`Events`、`Enemies`、`Bosses`、`Evolutions`、`Balance`、`Rooms`（BFS 寻路网格）、`Codec`、`Checkpoint`、`GameServer` / `GameClient`。
- `app/src/main/java/com/dilao/abysssquad/`：`GameView`（总编排）、`Ui` + `Art` + `SpriteAtlas` + `SceneArt` + `Fx`（渲染与特效）、`GameAudio`、`Meta` + `SaveStore` + `Achievements`、`screen/` 下 11 个屏幕。

### 确定性
- 全部随机数走 `RunRandom`（可序列化的 PRNG 状态），同一 seed + 同一输入序列 → 逐帧一致的结果。
- 每日星盘按日期派生 seed，全球同一天同一局。
- 全量状态二进制序列化 + CRC32 封包，存档原子写入（`AtomicFile`），崩溃后可恢复。

### 性能
- 图集一次解码，静态地牢地面烘焙进缓存位图，逐帧不再生成 Bitmap。
- 角色帧带永久 `cellCache`（这一条修掉了一个每帧 `Bitmap.createBitmap` 的严重性能 bug）。
- 粒子/飘字/光束全部对象池化（900 粒子 / 120 地面痕迹 / 60 飘字 / 40 光束），渲染特效层避免逐帧分配；核心模拟仍存在少量对象分配。
- 渐变用 20 槽 `LinearGradient` shader 缓存；辉光位图绘制半径上限 190px。
- 硬加速 Canvas（`LAYER_TYPE_HARDWARE`）。

### 资源
- 美术：`scripts/create_art.py`（+ 9 个 `_art_*.py` 模块，Pillow 程序化绘制，2px 描边 + 边缘光 + 自发光，4 帧动画）。
- 音频：`scripts/create_audio.py`（纯标准库 `wave`/`struct`/`math`，合成正弦/三角/方波 + ADSR + 滤波 + 多抽头延迟混响）。
  - 20 个音效 44.1kHz/16bit/mono，4 首循环音乐 OGG Vorbis。
  - 四首曲子是真正写出的和声进行（C 大调五声 I-vi-IV-V / A 小调 i-VI-III-VII / D 小调 / E 弗里几亚），不是随机噪声。
  - 峰值精确控制在 -3 ~ -13 dBFS，无削波；循环接缝振幅 < 0.001。
- 两个脚本都可重跑复现全部资源，不依赖任何付费 API。

## 五、验证

```powershell
# 编译
$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"
.\gradlew.bat --offline assembleDebug

# 数值探针（540 局全量，约 90 秒）
$srcs = @(Get-ChildItem core\src -Recurse -Filter '*.java' | ForEach-Object FullName) + @((Resolve-Path tests\PlayProbe.java).Path)
javac -encoding UTF-8 -d build\probe2 $srcs
java -ea -cp build\probe2 PlayProbe 3 5 0
```

探针是一个**带人类缺陷**的 bot：注入 180–320ms 反应延迟、±15% 走位漂移、每 2–4 秒换向抖动、10% 技能漏放率，并跑三档选牌策略（贪心 / 流派向 / 最优）。主指标取**流派向**——即真人的典型行为。

### 测试套件（13 套，`scripts/test.ps1`）

| 套件 | 守护什么 |
|---|---|
| CoreTests | 数据自检 / 确定性 / 存档往返 / 全流程可达 |
| RelicEffectTest | 60 件遗物逐件 A/B |
| EventContractTest | Events.TYPE 与 resolveEvent 的对应 |
| BossChargeTest | 首领冲锋状态机真的推进 |
| IdRolloverTest | 实体 id 不越出存档契约 |
| WeaponFormTest | 三种武器形态都可达且产出不同 |
| CrossSchoolTest | 6 组跨流派逐组 A/B + 门槛 |
| ClassRulesTest | 12 职业规则有效且真的接线 |
| DoctrineEffectTest | 18 张天赋牌收益与代价两面 |
| MetaNodeTest | 32 个元进度节点逐个有效 |
| PactEffectTest | 12 条契约词条逐条 A/B |
| EventVarietyTest | 36 个事件效果指纹两两不同 |
| ContentAudit | 数据表 / 平衡预算 / 契约软性偏差（v2.3 新接入） |


### 实测结果（v2.3 为 180 局 `/3 种子`；v2.2 为 480 局 `/8 种子`）

| 契约 | 目标 | 实测（v2.3，180 局） | 实测（v2.2，480 局） |
|---|---|---|---|
| 漫游 | 92–98% | **100%** | 100% |
| 远征 | 78–88% | **91.7%** | 95.8% |
| 试炼 | 55–68% | **50.0%** | 63.5% |
| 深渊 | 28–40% | **25.0%** | 31.3% |
| 炼狱 | 10–18% | **11.1%** | 13.5% |

> **关于 v1.0 那组数字**：v2.2 重新校准难度时发现，旧 README 记录的
> 88.5/59.4/46.9/24.0/18.8 **与当时的代码不符**——用同一探针、同一参数重跑
> v1.0 基线（`c739ab4`）得到的是 **99.0/99.0/95.8/84.4/71.9**。
> 也就是说旧曲线从漫游到炼狱几乎没有梯度（71.9% vs 18.8%，差了 4 倍）。
> v2.2 把 `Balance.DAMAGE / HP / PACE` 三张表重做成了真正的阶梯
> （累计 2.4× 血量、2.4× 伤害、1.76× 节奏），上表是重测后的真实值。

> **为什么漫游是 100%**：探针 bot 的走位比真人稳得多（180–320ms 反应、±15% 漂移
> 仍然比多数玩家准）。它适合做**档与档之间的相对校准**，不适合当作真人的绝对胜率。
> 漫游档刻意不做致死压力，新手应该能过。

平均推进 13.0 / 15 站，进化触发率 100%，职业极差 30.0pp，0 崩溃 / 0 NaN / 0 超时。

缺陷回归：`tests/VerifyFixes.java` 13 项断言全 PASS。
完整验收记录见 `docs/release-verification.md`。

## 七、已知边界

- 联机仅限可信局域网；无公网穿透、无账号体系、无排行榜。
- 没有云存档、跨设备同步。
- 模拟器上帧率受 CPU/GL 转译层限制（真机显著更好）；这不是应用的性能问题，微基准已证明绘制开销正常。
- 无内购、无广告、无网络上报，全部数据留在本机。
